Decoding vs verifying

A JWT's header and payload are just Base64URL-encoded JSON, so anyone can read them — never put secrets in a payload. Checking the signature needs the secret or public key; this page decodes but doesn't verify, so it isn't a jwt token decoder and verifier or jwt decode with secret key tool. Verify signatures in your server code. For a jwt decoder and encoder (or jwt decoder to encoder), sign new tokens with a library on your server.

In code

  • jwt decode python — PyJWT: jwt.decode(token, options={"verify_signature": False}) to inspect (verify in production).
  • jwt decode in javascript — the jwt-decode npm package, or JSON.parse(atob(token.split('.')[1])) for simple tokens.
  • java jwt decode / spring boot jwt decode — JwtDecoder in Spring Security, or the jjwt library.
  • jwt decoder flutter (jwt decoder in flutter) — the jwt_decoder package.
  • jwt decode bash / jwt decoder cli — cut -d. -f2 | base64 -d (add padding if needed); in PowerShell (jwt decode powershell), split on “.” and Base64-decode the second part.
  • decode jwt in postman — JSON.parse(atob(token.split('.')[1])) in a test script.
